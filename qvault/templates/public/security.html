Levels of approval security

Each level closes a gap the one before it leaves open.

  1. 0

    One person decides

    A single login can approve. Protects against nothing once that person is wrong, careless or impersonated.

  2. 1

    Several people click approve

    The rule needs more than one person, but the approvals are rows in the provider's database. Protects against one careless person; not against whoever can edit that database.

  3. 2

    Each approval is a signature

    Approvers sign the exact text with their own keys, so anyone can check who agreed to what. With classical signatures (RSA, ECDSA) a future quantum computer could forge them, and an approval record has to stay believable for years.

  4. 3

    Post-quantum signatures in a witnessed log {{ badge('Q-Vault is here', 'info') }}

    Approvals are post-quantum signatures ({{ default_sig }} by default). Every signature and outcome goes into an append-only log whose signed heads an independent witness co-signs, so the record can't be quietly rewritten, and any decision can be checked offline. The status page shows whether the witness is current.

What Q-Vault doesn't do

  • It doesn't stop collusion. If enough approvers agree to something wrong, it passes. Choose the rule and the people with that in mind.
  • The password key is held by this server. If you sign on the web, your signing key is stored here encrypted under your password, and the server unlocks it when you sign. Someone who controls the server and captures your password could sign as you. A key on the phone app is made on the phone and never leaves it.
  • We can't reset your password. It also unlocks your signing key. What you can do instead.
  • The witness is only as independent as whoever runs it. Today the Q-Vault team runs the one witness, as a separate service with its own key. It catches a rewritten database; it can't protect you from us.
  • Files are encrypted for the vault, not for each person. The server can decrypt a vault's files to give them to its members.
  • The connection isn't post-quantum. HTTPS to this site is whatever the hosting provider offers. The post-quantum claims cover signatures and the log.

  • Payments run on a test network. Treasury payments use Ethereum's Sepolia test network, not real money.

Check a decision offline

  1. Get the decision's file: an approver uses Export for verification on the decision page, or shares its public link.
  2. Download the offline verifier. It's one HTML file with the post-quantum library inside; open it with the network off and drop the file on it.
  3. Or run python -m qvault.verify decision.qvault.json --expect-log <fingerprint> --expect-witness <fingerprint> from the source. Exit code 0 means verified.

The fingerprints pin the log's and the witness's keys; get them from somewhere other than the file. This server publishes them, with its newest signed head and the newest head a witness co-signed, at the public signed head (no sign-in). Save it and run python -m qvault.verify checkpoint.json to check its signatures; the key_fingerprint values in it are the ones to pin. What each check proves.

Audit status

{{ badge('Not independently audited', 'warning') }}

No outside firm has reviewed Q-Vault. It is a university project. Its parts were reviewed internally for correctness and security as they were built, and an adversary lab report records the attacks run against it and what they found. Neither is a substitute for an audit.
