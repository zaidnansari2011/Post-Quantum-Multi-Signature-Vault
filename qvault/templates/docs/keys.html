Registering creates a post-quantum signing key that is yours alone. Approving something means signing it with that key, which is what makes an approval provably yours and stops it being undone by editing a database.

Where your private key lives

Not on this server in any readable form. Your password is stretched with Argon2id into a key-encryption key, which wraps your private key under AES-256-GCM. The server stores the ciphertext and never the password, so stealing the entire database still does not get anyone your signature.

The consequence is that nobody can recover your key for you. There is no reset.

Changing your password

Because your password protects your key rather than merely admitting you, changing it re-encrypts your key material. Every key you hold — active and retired — is unwrapped under the old password and re-wrapped under the new one, in a single transaction, and the salt is rotated. If anything fails, nothing changes.

Two kinds of custody

Server-held keys — the key that seals the audit record, and each vault's file-encryption key — are wrapped under the server's master key. The scheduler can replace them with nobody present.

Your signing key is locked with your password, which the server never holds. It therefore cannot be replaced unattended: the system flags it as due and you replace it yourself. That limitation is the security property working, not a gap.

Retire but retain

Replacing a key never deletes it. The old key stops signing and keeps verifying, so every signature it ever made still checks out. Old files stay readable too: each stored file records exactly which key encrypted it, so rotating a vault key cannot strand anything.

This is why replacing a key is safe, and why a signature from years ago still verifies against a key that has long since been retired.
