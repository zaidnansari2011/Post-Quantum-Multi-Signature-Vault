Every other part of this system proves things about a finished decision. The trace shows the middle of one: the exact bytes, in order, as an operation happens. Open it in a second window and drive the application in the first.

What it proves, and what it does not

Showing source code proves nothing by itself. A page can print whatever code it likes, so a code panel is a claim, not evidence. Two things make this page more than that.

The source is read from the running function at the moment it is called, not stored alongside the page, so what is displayed is the code that executed rather than a copy of it that could have drifted. And every derived value is shown with the input that produced it, so you can leave this application entirely and get the same answer: 

echo -n <hex> | xxd -r -p | sha256sum

That command appears under every value small enough to carry it. If a digest on this page were invented, one paste into your own terminal would expose it. That, rather than the code, is why the page is worth anything.

What cannot be shown

The trace shows the Python in this repository. It cannot show the interior of ML-DSA or SLH-DSA: those are compiled implementations the application calls, so for a signing step you see the complete call — the message, the key, the signature, the verdict and the time it took — and not the lattice arithmetic in between. The page says so on the step itself rather than implying a visibility it does not have.

A vote, step by step

Casting one vote records nine steps. Read in order they are the whole argument of this system:

StepWhat to look at
Build the bytes to be signed The message in full. It names the proposal, the decision and the signer, so an approval cannot be replayed as a rejection or attributed to anyone else.
Derive the key-encryption key Argon2id, with its real parameters. The slowest step on the page, deliberately.
Unwrap the private key The key is withheld; its size is not. It exists in memory for two steps.
Sign The signature's size is a research result in itself — compare ML-DSA against SLH-DSA on the algorithms page.
Verify before releasing Runs on every signature this server produces, before the bytes leave the function that made them. Normally unreachable; retained anyway.
Append to the audit chain The previous entry's hash is an input to this one. That single line is the whole tamper-evidence property.
Prove the log contains its own past Before signing a new root, the previously signed root must still be a prefix of the tree. If it is not, nothing is signed, and the stall is the alarm.
Recompute the Merkle root Every entry folded into one value. Compare it against the root on Audit.
Sign the checkpoint What an independent witness is offered, and what an exported decision carries.

Why it is switched off by default

It is an instrument, not a feature. It prints real values from real operations into one process-wide buffer, so it is restricted to administrators and disabled unless a deployment turns it on. Nothing on it is authoritative and nothing else reads it: the record is the audit log, and the evidence is the exported decision.

No secret is shown. Passwords and derived keys are withheld entirely — not their length, not a hash of them — and everything the page does display is either public by construction or something you can recompute yourself.
